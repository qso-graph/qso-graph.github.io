QSO Graph Trust

QSO Graph Trust signs and uploads your QSOs to ARRL's Logbook of The World (LoTW). It's a security-hardened library and command-line tool written in Rust: your key stays in your computer's credential store, every file it reads is tested against millions of broken and malicious files, and no key data is left in memory it frees.

It's part of the QSO Graph Project, and a ground-up rewrite, not a method-by-method port of TQSL. What it does was decided from the sources below, and how it does it is its own.

Security — Our #1 Priority​

Your key stays in your computer's credential store, leaving it only to sign or into a backup QSO Graph Trust encrypts itself. QSO Graph Trust is built to the standard of enterprise security software, and every point below is a test or a check that runs on every change:

  • OS credential stores only: the macOS Keychain, Windows Credential Manager or the Secret Service on Linux. Never a key file, and never a password or passphrase needed on the command line.
  • Nothing it writes holds your key or a password, and no key data is left in memory it frees. A custody test searches every file, output, log and the program's own memory to prove it.
  • Every file it reads is tested against millions of broken and malicious files (fuzz testing), and every length and count is capped, so a bad file is refused rather than crashing it.
  • Memory-safe Rust: no unsafe code in the library, the command line or anything that parses a file. The one exception is the small binding to AWS-LC, the cryptography library, which is also the only C or C++; policy checks enforce both.
  • Only LoTW, only HTTPS, only ARRL's roots, with the server's certificate always checked.
  • A locked supply chain: pinned dependencies, policy checks and CodeQL on every pull request, and signed, notarized and attested releases.
  • Nothing merges until it passes: over 450 tests, over 2.5 million broken and malicious test files, eight security policy checks, a search of memory and every file written for any trace of a key, and GitHub's CodeQL code scanning, on every change.

How each is tested, and how to report a security problem privately: SECURITY.md.

Sources​

  • ARRL's LoTW developer documentation: developer information, the signed log, .tq8, submitting QSOs, LoTW's PKI, certificate security, station locations, TQSL's command line, and the LoTW Trusted Partners guidelines.
  • TrustedQSL: its source at v2.8.7, read for what LoTW receives; tqsllib's API documentation; and TQSL's change log. QSO Graph Trust carries two things of TQSL's, both ARRL's, under ARRL's terms: the TQSL configuration (config.xml), from which its LoTW tables are generated, and ARRL's root and CA certificates (the 2015 pair as TQSL embeds them, the 2023 pair as ARRL issues them in a .tq6). TQSL 2.8.7, built from its own source, is the reference its signed records and signatures are tested against, byte for byte.
  • Other open-source projects: rfrht's qso-web, credited below, and a survey of 126 ham-radio Rust crates on crates.io, which found no other LoTW signing crate.
  • Standards: ADIF 3.1.8; RFC 5280 (X.509 certificates), RFC 4055 and RFC 8017 (RSA), RFC 1952 (gzip); W3C XML 1.0.

Who it's for​

  • Hams who want to sign and upload their QSOs to LoTW from the command line or their logger, with their key in their computer's credential store.
  • Authors of loggers and tools, who want LoTW signing inside their own program, through the library or the qg-trust command line.

What it does​

qg-trust signs your ADIF (.adi or .adx) or Cabrillo log with your LoTW callsign certificate and uploads it to LoTW, in one command. It brings over everything you have in TQSL from a TQSL backup: certificates, keys, station locations and the record of what you have already signed. It also requests and renews certificates and manages station locations. Loggers that run tqsl can run qg-trust with the same options, exit codes and final status line.

How it's different​

  • Your key stays locked away. It lives in your computer's own credential store (the macOS Keychain, Windows Credential Manager, or the Secret Service on Linux), never as a file someone could copy, and leaves it only to sign.
  • Every QSO is checked by ARRL's own rules before it's signed. A QSO LoTW would refuse is named, with the reason, and the rest are signed. Signatures are byte for byte what TQSL makes.
  • It works inside the program you already use. Another logger or a script can sign and upload for LoTW directly, and the library puts signing inside your own program.
  • It's signed. The macOS program is signed by QSO Graph and notarized by Apple, the Windows program is signed by QSO Graph, and the Linux packages and their repositories are signed with QSO Graph's release key.

Install​

macOS (Apple silicon) and Linux, with Homebrew:

brew install qso-graph/tap/qso-graph-trust

Debian, Ubuntu:

sudo curl -fsSL -o /usr/share/keyrings/qso-graph.gpg https://packages.qso-graph.net/qso-graph.gpg
echo "deb [signed-by=/usr/share/keyrings/qso-graph.gpg] https://packages.qso-graph.net/apt stable main" | sudo tee /etc/apt/sources.list.d/qso-graph.list
sudo apt update && sudo apt install qso-graph-trust

Fedora, RHEL, Rocky:

sudo curl -fsSL -o /etc/yum.repos.d/qso-graph.repo https://packages.qso-graph.net/qso-graph.repo
sudo dnf install qso-graph-trust

Windows: download qg-trust-<version>-windows-x86_64.zip from the latest release and put qg-trust.exe on your PATH. Every release also has the macOS and Linux programs, and SHA256SUMS.txt to check them against.

With Rust: cargo install qso-graph-trust-cli.

Sign and upload a log​

qg-trust import ~/tqsl-backup.tbk     # certificates, keys, locations and your signing record
qg-trust cert list                    # what you have, and when each certificate expires
qg-trust send mylog.adi -l Home       # sign mylog.adi for station location Home and upload it

A key that TQSL protected with a password is asked for once, when you import it, with what you type hidden. send leaves out QSOs you signed before unless you ask, and keeps mylog.tq8 beside the log. qg-trust sign mylog.adi -l Home signs without uploading; qg-trust upload mylog.tq8 uploads it later. To sign only some dates, add -b 2026-01-01 and -e 2026-06-30.

When ARRL starts issuing under a new root, its .tq6 brings the root, and qg-trust import names it with its SHA-256 fingerprint before trusting it: run it again with --trust-root <fingerprint> once you know it is ARRL's. A new root in your own TQSL backup is trusted and named. qg-trust root list shows every root your certificates chain to, and qg-trust root remove <fingerprint> stops trusting one you accepted.

From a logger, the tqsl options work as they are:

qg-trust -x -d -l "Home" -a compliant -u mylog.adi

qg-trust --help lists everything, and the command line's page has every command, option and exit code.
